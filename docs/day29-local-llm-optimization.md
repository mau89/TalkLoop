# День 29. Оптимизация локальной LLM

Задача — настроить Qwen3.5 9B под ответы по локальной кулинарной книге:
короткие ответы, точные количества, дословные цитаты и корректный отказ, если
в найденных материалах нет подтверждения. Обучение весов не выполняется:
оптимизируются параметры инференса и инструкции.

## Шаг 1. Зафиксировать исходный вариант

База реализации — коммит Дня 28 `45aa20a`. Индекс, поиск, порог 0,86,
выбор пяти фрагментов из десяти, память задачи, пищевые инварианты и проверка
цитат одинаковы во всех вариантах. Поиск локальный, через ONNX E5; все вызовы
генерации, памяти и проверки — к Ollama на Mac. Облачных моделей в прогоне нет.

Исходная Qwen3.5 9B Q4_K_M имеет в своей конфигурации temperature=1,
presence_penalty=1,5, top_k=20, top_p=0,95. Приложение раньше не переопределяло
эти параметры. Окно — 32 768, лимиты: ответ 2048, память 2600, проверка 1200.
Thinking отключён и до, и после настройки.

**Для чего:** сравнить оптимизацию с фактическими прежними параметрами, а не
с произвольно ухудшенной исходной моделью. Исходные шаблоны и проверки сохранены.

## Шаг 2. Подобрать параметры

Профиль `parameters` задаёт temperature=0 и presence_penalty=0; окно 24 576;
максимум 1600 токенов для ответа, 1400 для памяти и 400 для проверки цитат.
Меньший явный лимит вызывающего кода всегда сохраняется. Явная temperature
вызывающего кода имеет приоритет над значением профиля.

**Для чего:** сократить случайные переформулировки и длинные служебные ответы.
Штраф за повторение слов отключён, поскольку цитата должна повторять оригинал.
Сам по себе меньший max tokens не ускоряет уже короткий ответ; важен фактический
объём сгенерированного текста. Усечение по лимиту остаётся ошибкой проверки.

Окно выбрано с запасом относительно контрольных запросов, а не как универсальный
предел для любых диалогов. Проверка размера по UTF-8 байтам консервативная,
учитывает добавленные инструкции и резерв под ответ. Длинный диалог может раньше
потребовать новой задачи; скрытого обрезания или перехода в облако нет.

## Шаг 3. Изменить prompt под кулинарный RAG

Профиль `optimized` добавляет специализированные инструкции к существующим
правилам; JSON-схемы и проверка дословности не меняются:

- Память: исходные инструкции сохранены; настраиваются temperature и лимит.
  Дополнительный prompt для памяти проверен отдельно и отклонён, поскольку
  ухудшил дословное копирование. Его результаты и диагностика сохранены.
- Ответ: обычно 1–3 утверждения, только запрошенные факты. Для нескольких норм
  ингредиентов — одно утверждение с непрерывной цитатой нужного списка.
  Не называть выбранные ингредиенты полным составом блюда.
- Проверка: короткий reason, проверка каждого заявленного факта. Не считать
  отсутствие непрошенных ингредиентов ошибкой, если ответ не заявляет полноту списка.

**Для чего:** сократить лишний текст и ложные отказы при проверке частичного
списка ингредиентов. Ошибки памяти оцениваются отдельно. В prompt нет ответов на контрольные
вопросы и чисел из эталонных рецептов. Нельзя принять выдуманную цитату или
пропустить существующие проверки ради лучшего процента успеха.

Это прикладной system-prompt-шаблон. Нативный chat template Qwen не заменяется:
Ollama по-прежнему формирует служебные токены модели самостоятельно.

## Шаг 4. Проверить квантование той же модели

Исходный вариант — `qwen3.5:9b` с Q4_K_M, дополнительный —
`qwen3.5:9b-q8_0` с Q8_0. Q8 скачана отдельно; никаких попыток восстановить
8-битные веса из уже сжатых 4-битных весов нет. Архитектура и число параметров
одинаковые; точные версии и digest сохранены в метаданных прогона.

**Для чего:** сравнить компромисс памяти, скорости и качества при том же
оптимизированном prompt. Q8 не считается лучшим заранее. Загрузка весов не
включается во время ответа, но занимает дополнительное место на диске.

## Шаг 5. Сравнить качество, скорость и ресурсы

Воспроизводимый полный прогон после загрузки моделей и запуска сервера книги:

```sh
python3 tools/day29/compare.py
```

Основной тест: q04 (температура и время булочки), q07 (три нормы для оливье),
q10 (отказ на отсутствующий борщ), по три независимые попытки. Каждый запрос
получает новый TalkLoopAgent без истории; модель не видит эталонные ответы.
Порядок профилей фиксирован: исходный, оптимизированный Q4, оптимизированный Q8.
Дополнительно исходный, оптимизированный Q4 и оптимизированный Q8 проверяются на q01, q03, q08,
которые не использовались для подбора формулировок нового prompt.

Перед каждым профилем один короткий прогрев, исключённый из замеров. При смене
модели предыдущая выгружается, чтобы память двух моделей не суммировалась.
Вопросы выполняются последовательно: параллельная генерация исказила бы время.
Основной прогон начат после завершения скачивания Q8. Предварительные прогоны
сохранены отдельно и не включаются в основное сравнение.

Полное время запроса включает память, поиск, генерацию, проверку и возможное
исправление. Медиана завершённых запросов отличается от медианы всех попыток;
ошибки не маскируются быстрыми «успехами». При ошибках benchmark возвращает
ненулевой код, сохранив все попытки; скрипт продолжает остальные профили.

Раз в секунду сохраняются `/api/ps` и RSS процессов Ollama. `size_vram` —
выделенная моделью память по данным Ollama, а не потребление всего Mac. RSS —
резидентная память процессов из `ps`, KiB. На Mac общая память CPU/GPU:
эти два показателя нельзя складывать. Сэмплирование может пропустить краткий пик.
Энергия и пиковая память всей системы не измерялись. Остальные приложения Mac
не закрывались; малые различия времени не означают доказанного ускорения.

Автоматические оценки исходного набора сохранены. Итоговое качество требует
чтения самих утверждений и сверки цитат с исходными фрагментами: формулировка
«от 170 до 180» может не совпасть с шаблоном, хотя ответ правильный.

## Повторить отдельный вариант

```sh
python3 tools/day29/run_profile.py --profile baseline --label baseline
python3 tools/day29/run_profile.py --profile parameters --repeats 1 --label parameters
python3 tools/day29/run_profile.py --profile optimized --label optimized-q4
python3 tools/day29/run_profile.py --profile optimized --model qwen3.5:9b-q8_0 --label optimized-q8
```

Только ответы, без мониторинга ресурсов:

```sh
./gradlew :cli:day29 --offline -q --console=plain --args='--profile optimized --repeats 3'
```

Профиль `baseline` остаётся доступен; `:cli:day28` по умолчанию продолжает
использовать прежний нетюнингованный транспорт. Данные новых запусков пишутся
в исключённую из Git папку `day29-data`. Принятые результаты архивируются в docs.

Параметры, метрики и квантования сверены с первичными источниками:
[Ollama Modelfile](https://docs.ollama.com/modelfile),
[Chat API](https://docs.ollama.com/api/chat),
[официальные варианты Qwen3.5](https://ollama.com/library/qwen3.5/tags).


## Дополнительная проверка памяти диалога

```sh
./gradlew :cli:day29 --offline -q --console=plain --args='--profile optimized --model qwen3.5:9b-q8_0 --dialogue --repeats 1 --output day29-data/dialogue-optimized-q8.json'
```

Сначала пользователь задаёт цель со списком продуктов и запрещает пересчёт
порций, затем уточняет «А майонеза сколько для него?», затем называет новое блюдо.
Перед каждым ходом создаётся новый агент, восстанавливающий тот же
InMemoryChatHistoryStore; явно проверяются точное восстановление памяти,
сохранение цели и ограничения. Это проверка восстановления объекта агента,
а не физического перезапуска Android или сериализации файла на телефоне.
Цитаты и ответы проходят весь локальный RAG, как в основных запросах.


## Результаты основного сравнения

MacBook Pro, Apple M2 Max, 64 ГБ, macOS 27.0.1, Ollama 0.40.2.
Во всех вариантах девять попыток: по три на q04, q07 и q10.

- Исходный Q4: завершены 7/9, две ошибки валидации памяти. Запрошенные
  числа/корректный отказ получены в 7/9; полностью подтверждены собственными
  цитатами 5/9. В одном ответе к ингредиентам добавлена корица, отсутствующая
  в приведённой цитате; в другом — неподтверждённое объяснение современных
  вариантов салата. Автоматический проверяющий пропустил эти недостатки.
- Оптимизированный Q4: завершены 9/9, правильные числа/отказы 9/9, строгое
  соответствие формулировкам источника 6/9. Во всех трёх ответах про салат
  пропущено слово «примерно» перед четырьмя порциями, хотя цитата его содержит.
- Оптимизированный Q8: завершены 9/9, числа/отказы и оговорки источника сохранены
  в 9/9. Ни одна из шести опубликованных цитат не выходит за исходный фрагмент.

Медиана **полного времени завершённого запроса**: исходный Q4 — 47,559 с;
оптимизированный Q4 — 28,898 с; оптимизированный Q8 — 32,778 с.
Для вопроса о салате: 53,089 → 37,110 → 38,019 с соответственно.
Быстрый отказ на отсутствующий рецепт входит в медиану всех трёх вариантов;
это не время генерации одного токена. Ошибки исходного варианта исключены
только из медианы завершённых запросов и явно посчитаны выше.

Максимальная выделенная память модели (`size_vram`): 6,229 → 6,473 → 10,104 ГиБ.
Максимальный RSS процессов Ollama: 8,979 → 8,176 → 11,782 ГиБ.
Таким образом, уменьшение окна само по себе не гарантировало снижения
`size_vram` в этом запуске; Q8 потребляет больше памяти. Показатели RSS и
`size_vram` пересекаются и не суммируются.

**Выбор для этого Mac — Q8 с оптимизированным профилем:** оговорки книги
сохранены точнее, память укладывается в 64 ГБ. Q4 остаётся более экономной
альтернативой. Девять попыток не доказывают безошибочность на всех рецептах.
Исходные отчёты, замеры и ручная проверка находятся в [day29-results](day29-results/).

## Готовые настройки и где их менять

Профиль приложения находится в
[OllamaTuning.kt](../core/src/commonMain/kotlin/com/mau89/talkloop/llm/OllamaTuning.kt).
В одном месте меняются:

- `COOKBOOK_OLLAMA_MODEL` — выбранная модель `qwen3.5:9b-q8_0`.
- `temperature = 0.0` — меньше случайных переформулировок.
- `presencePenalty = 0.0` — не мешать дословному повторению цитат.
- `contextWindowTokens = 24576` — размер окна контекста.
- `answerMaxTokens = 1600` — предел ответа.
- `memoryMaxTokens = 1400` — предел служебного ответа памяти задачи.
- `verdictMaxTokens = 400` — предел проверки цитат.
- `recipePrompts = true` — специальные инструкции для ответов по книге;
  тексты инструкций ниже в этом же файле.

В профиле Дня 29 thinking выключен (`think: false`); переключатель в приложении
позволяет включить его для сравнения. Новая установка
приложения выбирает Q8 по умолчанию. Сохранённый ранее выбор модели сохраняется:
в «Агент → Настройки» выбери Ollama и укажи `qwen3.5:9b-q8_0`.
Все перечисленные параметры доступны в «Агент → Настройки → Ollama».
Поля проверяются перед сохранением; запятая и точка в дробных числах принимаются.
Кнопки «До настройки · Q4» и «День 29 · Q8» заполняют исходный и принятый
профили. После изменения нажми «Сохранить и применить»: параметры сразу
передаются новому клиенту, включая память и проверку цитат, и сохраняются
на Android и iOS между запусками. Для возврата к Q4 достаточно выбрать
`qwen3.5:9b`; кнопка исходного профиля также возвращает прежние параметры.
Изменение в интерфейсе не требует пересборки.

Для отдельного запуска Ollama подготовлен [Modelfile](../tools/day29/Modelfile):

```sh
ollama pull qwen3.5:9b-q8_0
ollama create talkloop-cookbook:day29 -f tools/day29/Modelfile
ollama show talkloop-cookbook:day29 --parameters
```

Имя `talkloop-cookbook:day29` — локальная копия конфигурации с теми же весами,
без второго скачивания. Сам Modelfile задаёт параметры генерации; RAG, память,
разные лимиты этапов и инструкции обеспечивает приложение. Приложение продолжает
использовать исходный тег Q8 и передаёт профиль при каждом запросе.

В [request-options.json](../tools/day29/request-options.json) сохранены фрагменты
параметров HTTP-запросов для ответа, памяти и проверки. Для полного запроса
нужно добавить `messages`; RAG-приложение также передаёт соответствующую JSON-схему.


В отчётах benchmark поле `maxTokens=2048` обозначает исходный лимит вызывающего
агента; эффективный лимит на HTTP-запросе ограничен профилем `tuning` до 1600.
Служебные этапы аналогично получают свои пределы. В приложении основной лимит
агента также установлен в 1600.


## Дополнительные результаты и границы применения

На трёх дополнительных вопросах исходный Q4 завершил 3/3, но в вопросе о рисе
пропустил запрошенное время: полнота 2/3. Оптимизированные Q4 и Q8 завершили 3/3
и указали все запрошенные значения. У q03 автоматическая оценка остаётся false
из-за длинного тире в «30—120»: вручную значение подтверждено исходным текстом.
Исходный шаблон проверки не меняли ради результата.

**Тест памяти диалога не пройден: 0/3.** Генерация ответов происходила локально
на всех трёх ходах, однако `goal=null`: первые два раза цель попала в constraints,
на третьем ходе constraints тоже пуст. В первых двух ответах Q8 вновь опустила
слово «примерно» перед четырьмя порциями. Уточнение «для него» разрешилось в оливье
правильно, но это не доказывает корректность остальных слоёв памяти.
Из-за assertion результат benchmark сохраняется как ошибка с raw modelReplies;
ранний выход также не позволяет подтвердить последующее точное восстановление
previousMemory. Этот сценарий не входит в девять основных одиночных запросов.

Профиль принят для коротких ответов по книге. В длительном диалоге нужно отдельно
проверять память цели и оговорки; оптимизация параметров не устранила эту проблему.
На основе основного теста нельзя заявлять полную стабильность всего агента.

Проверки реализации: 173 JVM-тестов, ошибок 0; Android debug APK,
CLI и компиляция iOS Simulator — успешно. Проверено создание локальной
`talkloop-cookbook:day29` из Modelfile и сохранение её параметров Ollama.


### Настройки в приложении

Для Дня 29 параметры возвращены в интерфейс. Отредактируй числа и переключатели
в «Агент → Настройки → Ollama», затем нажми «Сохранить и применить».
Пресеты заполняют поля и выбирают Q4/Q8; изменение конкретного числа доступно
после любого пресета. Лимиты относятся ко всему локальному RAG-пайплайну,
включая служебные запросы; фактический ответ может быть короче лимита.

Проверены 174 теста core и 24 теста приложения, сборка Android и компиляция iOS.
В эмуляторе температура изменена на 0,3, сохранена и восстановлена в форме
после перезапуска. Затем применён исходный профиль Дня 29 с температурой 0
и Q8. Результат сохранён в [ui-validation.json](day29-results/ui-validation.json).
Основные замеры выше выполнены с thinking=false; новый переключатель по
умолчанию сохраняет это значение и не меняет условия проведённого сравнения.
