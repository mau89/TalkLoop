# День 31 — ассистент разработчика

## Использование

1. При отсутствии локальной E5 выполните `tools/day21/run.sh prepare`.
2. Постройте индекс: `.day21-venv/bin/python tools/day31/index_project.py`.
3. Запустите сервер: `./gradlew :server:run`.
4. В обычном чате «Агент» выберите рабочее подключение Claude или Ollama.
5. Отправьте `/help`, `/help Где реализован MCP?` или
   `/help Как устроен проект и какая сейчас git-ветка?`.

Команда есть в меню MCP и подсказках при вводе `/`.
Переключатель кулинарной книги не влияет на `/help`.
Если MCP отключён в настройках, документация остаётся доступной,
а ассистент сообщает, что текущая ветка неизвестна.
Если сервер/индекс недоступен, показывается ошибка с инструкцией подготовки;
ответ без контекста не генерируется.

## RAG

Корпус: README и все Markdown-файлы в `docs`, включая
[описание структуры и API](project-architecture.md).
Исходные тексты режутся по заголовкам Markdown и окнам по 320 токенов
с перекрытием 48. Используется прежняя `intfloat/multilingual-e5-small`,
384 измерения, ONNX на CPU; новый индекс не смешивается с кулинарной книгой.
На запрос выбираются пять фрагментов `structural`, которые передаются LLM
с именем файла, разделом и номером источника. Вся документация в промпт не загружается.
Список источников и блок с точной веткой/commit добавляет приложение из данных
поиска и MCP, без генерации этих метаданных моделью.

Индекс — снимок. После правки README/docs повторите индексацию и перезапустите
сервер. Наличие источника не гарантирует подтверждение каждого утверждения:
модель получает инструкцию ссылаться на документы и признавать пробелы;
отдельного семантического проверяющего для `/help` пока нет.

## MCP

Отдельный endpoint `http://127.0.0.1:8082/mcp` публикует `git_branch`.
Приложение выполняет настоящий MCP discovery и `tools/call`; ветка читается
на сервере заново при каждом `/help`. Название ветки из старых отчётов не используется.
Инструмент read-only, не принимает путь или произвольную команду.
Для внешнего MCP-клиента можно добавить этот endpoint вручную.

## Проверка

Автотесты покрывают маршрутизацию `/help` до кулинарного поиска, состав промпта,
отключённый MCP, ошибки поиска, реальные ветки временного Git-репозитория,
detached HEAD и вызов инструмента через MCP. Python-тест проверяет полноту
Markdown-разделов и исключение файлов вне разрешённого корпуса.

```shell
.day21-venv/bin/python -m unittest discover -s tools/day31 -v
./gradlew :core:jvmTest :server:test :app:shared:testAndroidHostTest :app:androidApp:assembleDebug --offline --console=plain
./gradlew :cli:day31 -q --console=plain --args='Как устроен проект TalkLoop и какая сейчас git-ветка?'
```

CLI использует тот же `ProjectHelpTools` и `TalkLoopAgent`, получает документы
по HTTP, ветку через MCP и генерирует ответ локальной Ollama.
Результат сохраняется в `day31-data/last-help.json`.
Сохранённый результат контрольного прогона: [day31-result.json](day31-result.json).
