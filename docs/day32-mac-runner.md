# Mac как раннер ревью TalkLoop

## Установленная конфигурация

- Репозиторий: `mau89/TalkLoop`.
- Имя раннера: `talkloop-mac-a1`, единственная метка: `talkloop-review-mac`.
- Файлы раннера и его отдельные рабочие копии: `~/.local/share/talkloop-actions-runner`.
- Проверка доверенных заданий: `~/.local/share/talkloop-runner-policy`.
- Пользовательская служба: `~/Library/LaunchAgents/actions.runner.mau89-TalkLoop.talkloop-mac-a1.plist`.
- Ollama: существующее приложение на Mac, `127.0.0.1:11434`.
- Модель: существующая `qwen3.5:9b-q8_0`.

Официальный пакет GitHub Actions Runner для macOS ARM64 скачивается
из `actions/runner`, проверяется SHA-256 из GitHub Release и распаковывается
в отдельную папку. Регистрационные токены не выводятся и не коммитятся.
Раннер установлен как пользовательская служба, без `sudo`.
Другие раннеры и существующие настройки Ollama не меняются.

## Как работает задание

Это служба для GitHub Actions. Кнопка «Проверить PR» во вкладке приложения
«Ревью PR» запускает тот же анализатор через локальный сервер TalkLoop
независимо от этой службы. Остановка или удаление раннера отключает выполнение
Actions на Mac, а ручная проверка из приложения остаётся доступна при работающем
сервере и Ollama. Для остановки ручной проверки остановите сервер TalkLoop.
[Инструкция по экрану приложения](day32-automated-review.md#проверка-из-приложения).

GitHub назначает подходящий PR раннеру. До шагов workflow хостовая проверка
разрешает только `mau89/TalkLoop`, workflow `ai-review.yml`, инициатора `mau89`
и PR этого же владельца из того же репозитория. Fork PR и другие события
блокируются. Ручной запуск разрешён только владельцу.
Проверка лежит вне рабочей копии и подключена через
`ACTIONS_RUNNER_HOOK_JOB_STARTED` в локальном `.env` раннера.

Workflow получает отдельную копию репозитория, использует уже установленный
`/usr/bin/python3` (3.9+), проверяет Python-код пайплайна и вызывает локальную Ollama.
Дополнительный Python в систему не устанавливается. При необходимости запускается
установленное приложение Ollama в фоне. Отчёт загружается в GitHub Actions.
Сон или выключение Mac приводят к ожиданию доступного раннера; настройки сна
ради CI не менялись. Для работы службы нужен вход в учётную запись macOS.

## Влияние на обычную работу

Раннер в ожидании не выполняет модель и не запускает сборку Android/iOS.
Рабочая папка Android Studio не используется и не очищается: checkout и
очистка GitHub Actions происходят в отдельном `_work` раннера.

Во время ревью Qwen занимает память и использует GPU. Возможны замедления
IDE, эмулятора и других задач. Запросы приложения TalkLoop и ревью к одной
Ollama могут ожидать друг друга. Поэтому полного отсутствия влияния обещать
нельзя. Один раннер выполняет одно задание; в запросах ревью задано четыре
CPU-потока. `keep_alive=60s` позволяет Ollama освободить модель после простоя;
это параметр запроса, а не изменение глобальной конфигурации.

Раннер работает с правами текущего пользователя и не является песочницей
macOS. Поэтому нельзя расширять его на произвольные внешние PR. Хостовая
проверка ограничивает доверенные задания, но не заменяет отдельную учётную
запись или виртуальную машину для полностью недоверенного кода.

## Посмотреть состояние, поставить на паузу, возобновить

Из корня TalkLoop:

```shell
python3 tools/day32/mac_runner.py status
python3 tools/day32/mac_runner.py stop
python3 tools/day32/mac_runner.py start
```

Пауза сохраняет регистрацию и файлы. Раннер становится Offline и перестаёт
принимать задания. Текущее задание может прерваться, поэтому лучше ставить
на паузу, когда `busy=false`. Ollama и приложение TalkLoop не останавливаются.
Остановка и последующий запуск службы проверены при установке.

## Отменить настройку

Сначала отключите workflow, чтобы новые задания не ожидали удалённый раннер:

```shell
gh workflow disable ai-review.yml --repo mau89/TalkLoop
python3 tools/day32/mac_runner.py remove
```

Команда `remove` откажется удалять занятый раннер; дождитесь окончания задания.
Она останавливает и удаляет пользовательскую службу, снимает регистрацию
в GitHub и удаляет регистрационные файлы стандартной командой GitHub.
Текущий проект, модели Ollama и авторизация `gh` сохраняются.
Скачанные файлы раннера, `_work`, логи и папка политики могут оставаться
на диске для повторной установки; после удаления службы их можно стереть.

Для возвращения локального раннера нужен Python 3.12+:

```shell
.day21-venv/bin/python tools/day32/mac_runner.py install
gh workflow enable ai-review.yml --repo mau89/TalkLoop
```

Альтернатива — переключить workflow обратно на GitHub-hosted runner
и `--provider anthropic`, передав ключ через Actions secret.
Поддержка Claude сохранена в `review_pr.py`.
