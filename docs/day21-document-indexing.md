# День 21 — локальная индексация русской кулинарной книги

Пайплайн: русские рецепты → очистка HTML → две стратегии разбиения → локальные
E5-эмбеддинги → два JSON-индекса → сравнение поиска. Вкладка **«Документы»**
позволяет проверить оба индекса в приложении. Вопросы и найденные фрагменты
на русском. Поиск возвращает исходный текст рецептов; генерация ответа LLM
поверх фрагментов в это задание не входит.

## Книга и объём

Источник — [«Кулинарная книга» Викиучебника](https://ru.wikibooks.org/wiki/Кулинарная_книга).
Выбраны 53 страницы из категории «Хорошие рецепты»: супы, салаты, выпечка,
основные блюда, бульоны и соусы. Среди них луковый суп, плов, оливье, окрошка,
макароны по-флотски, кулич и булочки с корицей. На одной странице может быть
несколько вариантов рецепта; это подборка из книги, а не вся книга.

После очистки: **32 122 слова, 64,24 условной текстовой страницы** при 500 словах
на страницу. Это оценка объёма текста, а не число веб-страниц. Минимум проверяется
программно: 15 000 слов (=30 условных страниц).

Реестр источников — `tools/day21/sources.json`. Сохраняются текст статьи, списки,
строки таблиц ингредиентов и иерархия заголовков. Навигация, кнопки редактирования,
скрипты и списки сносок исключаются. Ошибки загрузки не превращаются в пустые
документы и не затирают предыдущий корпус. Викиучебник может менять рецепты;
локальные файлы фиксируют использованный срез и контрольные суммы текста.

Авторство: **участники Викиучебника**. Лицензия текста:
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/deed.ru).
Источник и атрибуция сохраняются в корпусе и чанках; в приложении есть подпись
авторов/лицензии и ссылка на исходный рецепт. Автоматическое извлечение меняет
формат представления текста, сохраняя содержание. При дальнейшем распространении
текстов следует сохранять авторство, ссылки и условия этой лицензии.

По просьбе пользователя книга заменила английские инструкции Bambu Lab.
Исходные реестры принтеров сохранены в `tools/day21/corpora/bambu/`, прежние
индексы на этом компьютере — в `day21-data/bambu-backup/`.

## Две стратегии: как отличить

Обе используют один корпус, один токенизатор, максимум **320 токенов текста**
и **48 токенов перекрытия** внутри длинного сегмента. Между файлами окна не переходят.

1. **Фиксированный** (`fixed`): окна по всему рецепту. В одном чанке могут оказаться
   ингредиенты, приготовление и начало следующего варианта рецепта.
2. **По разделам** (`structural`): отдельные сегменты по заголовкам. Состав и
   приготовление остаются раздельными, если у них есть отдельные заголовки.
   Короткий раздел сохраняется целиком, длинный делится окнами 320/48.

Чанк содержит `source`, `title`, `file`, `section`, `chunk_id`, `anchors`,
`strategy`, `char_start`, `char_end`, `token_count`, `section_count`,
`source_content_sha256`, `downloaded_at`, `attribution`, `text`, `embedding`.
Поле `models` сохранено для совместимости с прежним корпусом и пустое у рецептов.
Идентификатор стабилен для одинаковых источника, стратегии, границ и текста.
Позиции относятся к единому очищенному тексту `corpus.json`.

## Модель и хранение

`intfloat/multilingual-e5-small`, ONNX на CPU, **384 координаты**.
Версия: `614241f622f53c4eeff9890bdc4f31cfecc418b3`.
Настройки следуют [официальной карточке модели](https://huggingface.co/intfloat/multilingual-e5-small):
префиксы `passage:`/`query:`, название и раздел в представлении документа,
attention-mask mean pooling, L2-нормализация, косинусное сходство.
Предел 512 токенов проверяется вместе с метаданными: скрытого обрезания нет.

Первичная загрузка требует сети: модель около 448 MiB, токенизатор около 16 MiB,
плюс рецепты. Построение, сравнение и поиск после подготовки работают локально
без внешних API и ключей. JSON выбран для прозрачного учебного результата.
Большие данные и Python-окружение исключены из Git.

## Запуск

На этом компьютере окружение и индексы уже готовы. На другом компьютере нужны
Python 3.10+ и `curl`; из корня TalkLoop:

```shell
python3 -m venv .day21-venv
.day21-venv/bin/python -m pip install -r tools/day21/requirements-lock.txt
tools/day21/run.sh prepare
tools/day21/run.sh build
```

Альтернатива через Gradle: `./gradlew :cli:day21 --args='prepare'`, затем
`./gradlew :cli:day21`. Обновление рецептов — `prepare --refresh`, после него
требуется `build` и перезапуск сервера, который держит индексы в памяти.

```shell
tools/day21/run.sh search 'Как приготовить луковый суп с плавленым сыром?' --strategy fixed --limit 3
tools/day21/run.sh search 'Как приготовить луковый суп с плавленым сыром?' --strategy structural --limit 3
tools/day21/run.sh compare
```

## Сравнение на контрольных вопросах

`tools/day21/questions.json` содержит 12 русских вопросов с заранее заданными
источниками и подтверждающими фрагментами. Один вектор вопроса используется
в обоих индексах. Релевантность требует совпадения источника **и** хотя бы одной
подстроки подтверждения. Это небольшой набор для проверки поиска конкретных
фрагментов, не оценка всех возможных вопросов и не доля правильных ответов.

Результат настоящего прогона с локальной E5:

- **Фиксированный:** 273 чанка, средний размер 295,7 токена, медиана 320,
  минимум 55, максимум 320. 236 чанков пересекают разделы. JSON 3 874 205 байт,
  построение 16,878 с. Hit@1 = **8/12**, Hit@5 = **12/12**, MRR@5 = **0,7944**.
- **По разделам:** 782 чанка, средний размер 92,9 токена, медиана 66,
  минимум 2, максимум 320. Пересечений разделов нет. JSON 10 071 307 байт,
  построение 27,203 с. Hit@1 = **7/12**, Hit@5 = **9/12**, MRR@5 = **0,6319**.

Hit@K — доля вопросов с нужным чанком среди первых K; MRR@5 учитывает позицию
первого нужного чанка. Все результаты и неудачи сохранены в `comparison.json`.
У структурной стратегии в топ-5 не нашлись заданные фрагменты об добавлении масла
в майонез, заправке салата Нисуаз и сохранении голландского соуса тёплым.

На этом наборе фиксированные окна чаще находят нужный фрагмент: они сохраняют
больше соседнего контекста. Структурные чанки точнее соблюдают границы, но короткие
заголовки и разделы дают много маленьких фрагментов и дополнительных векторов.
Это объясняет разные размеры индексов. Объединение коротких подразделов можно
проверить отдельно; в текущем сравнении оно не используется. Время построения
зависит от прогрева CPU и не является строгим сравнением производительности.

## Проверка в приложении

1. Запустите локальный сервер: `./gradlew :server:run --console=plain`.
2. Откройте вкладку **«Документы»**. Каталог загрузится автоматически; если сервер
   запустился позже, нажмите **«Подключиться»**. На экране должно быть 53 документа
   и название русской кулинарной книги.
3. Оставьте режим **«Оба»** и вопрос **«Как приготовить луковый суп с плавленым сыром?»**.
   Нажмите **«Сравнить результаты»** и прокрутите вниз.
4. У **«Фиксированного»** первый результат содержит состав и приготовление вместе.
   У **«По разделам»** — раздел **«Луковый суп 1 / Приготовление»**.
   Нажмите **«Весь фрагмент и метаданные»**, чтобы увидеть границы и полный русский текст.
5. **«Показать ещё…»** открывает остальные результаты топ-5.
   **«Открыть источник»** ведёт к рецепту и его разделу.
6. Попробуйте плов и майонез из кнопок примеров. Режимы **«Фиксированный»** и
   **«По разделам»** позволяют искать только в одном индексе.

Android Emulator: `http://10.0.2.2:8080`. iOS Simulator: `http://127.0.0.1:8080`.
Для реального телефона в той же сети укажите `http://<IP-компьютера>:8080`.
На Android по USB можно выполнить `adb reverse tcp:8080 tcp:8080` и использовать
`http://127.0.0.1:8080`. Только открытие внешнего источника требует интернета.

Сервер: `GET /api/documents/status`, `POST /api/documents/search`.
Режим `both` вычисляет один вектор и ищет его в двух индексах.
Python-worker загружает модель один раз; диагностика — `day21-data/worker.log`.
Сбой worker не завершает сервер, следующий запрос запускает его заново.
Общий контракт приложения и сервера — `core/.../llm/DocumentIndex.kt`.

## Файлы и проверки

- `day21-data/corpus.json`: тексты, разделы, атрибуция и объём.
- `day21-data/raw/`: исходные статьи, в том числе HTML режима чтения.
- `day21-data/model/`: локальная модель и токенизатор.
- `day21-data/index-fixed.json`, `index-structural.json`: тексты, метаданные, векторы.
- `day21-data/comparison.json`: измерения и все контрольные результаты.

```shell
.day21-venv/bin/python -m unittest discover -s tools/day21 -v
./gradlew :server:test :app:shared:testAndroidHostTest :app:androidApp:assembleDebug --offline --console=plain
```

Проверки покрывают сохранение русского текста и хвоста, перекрытие, стабильность
ID, границы разделов, извлечение таблиц ингредиентов и статьи вместо навигации,
сохранение JSON, фильтры и релевантность с подтверждением. Серверные тесты проверяют
общий контракт, отклонение неверных запросов до инференса и ошибку недоступного индекса.
