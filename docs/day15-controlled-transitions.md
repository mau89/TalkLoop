# День 15. Контролируемые переходы состояний

## Маршрут задачи

Жизненный цикл остаётся конечным автоматом:

`planning → execution → validation → done`

Если проверка нашла дефекты, разрешён единственный обратный переход
`validation → execution`. Любое другое ребро отклоняется до изменения состояния.

Каждое событие, кроме начального `TASK_STARTED`, обязано содержать текущую
`expectedRevision`. Поэтому устаревшая команда и команда без ревизии не могут
перезаписать более новое состояние. Точный повтор уже принятого события остаётся
идемпотентным.

## Защита от схода с маршрута

- `beginTask` не заменяет незавершённую или приостановленную задачу. Для намеренного
  отказа от старого контекста остаётся отдельное явное действие «Начать новую задачу».
- На паузе принимается только `RESUMED`; отказ не меняет этап, шаг, ревизию или журнал.
- Журнал проверяет последовательность ревизий, уникальность ID, непрерывность этапов,
  допустимость каждого ребра и согласованность признака паузы.
- Предложение модели должно относиться к текущей ревизии и быть допустимым для
  текущего этапа.
- Явные просьбы начать реализацию во время планирования или завершить задачу до
  успешной валидации получают локальный объяснимый отказ без обращения к LLM.
- System prompt дополнительно содержит правило текущего этапа, поэтому модель знает,
  какие действия сейчас разрешены.

Старые сохранения без журнала по-прежнему читаются. Как только работа продолжается,
новые события записываются и проверяются по усиленному контракту.

## Проверка

`TaskStateMachineTest` покрывает:

- полную отрицательную матрицу переходов для всех четырёх этапов;
- неизменность состояния после каждого отказа;
- обязательную ревизию и защиту от конкурентных команд;
- все команды во время паузы и штатное продолжение после `RESUMED`;
- запрет тихой замены активной задачи;
- отказ ассистента от реализации до `PLAN_APPROVED` и от завершения до
  `VALIDATION_PASSED` без вызова модели;
- разрешение реализации сразу после утверждения плана;
- отклонение несогласованного журнала.

Полный набор проверок:

```shell
./gradlew :core:allTests :app:shared:allTests --console=plain
```
