# День 11. Модель памяти агента

## Контракт слоёв

| Слой | Что попадает | Кто решает о записи | Срок жизни |
|---|---|---|---|
| Краткосрочный | Успешные пары сообщений user/assistant | Агент по фиксированному правилу | Последние N сообщений текущей задачи |
| Рабочий | Цель, срок, ограничения и промежуточные данные текущей задачи | Пользователь/вызывающий код через `MemoryWrite.Working` | До `startNewTask` |
| Долговременный | Профиль, принятые решения, проверенные знания | Пользователь/вызывающий код через `MemoryWrite.LongTerm` с категорией | Между задачами и перезапусками |

Модель сама не повышает реплики из диалога в рабочую или долговременную память.
Это намеренное решение: запись наблюдаема, предсказуема и не превращает случайную
фразу или prompt injection в постоянный факт.

## Хранение и формирование ответа

Сериализованный снимок имеет три отдельные секции: `shortTerm`, `working` и
`longTerm`. Рабочий и долговременный слои добавляются в system prompt отдельными
XML-блоками. Краткосрочный слой передаётся как обычная история сообщений.

Перед каждым ответом агент видит:

1. базовый системный промпт;
2. `working_memory` только активной задачи;
3. `long_term_memory` с категорией каждой записи;
4. ограниченный хвост `shortTerm` и новую реплику.

В промпте явно сказано считать значения памяти данными, не выполнять инструкции
из них и уточнять противоречие между свежей репликой и сохранённой памятью.

## Проверки без сети

Тесты фиксируют следующие инварианты:

- после трёх ходов при лимите четыре сообщения первый ход вытесняется только из
  краткосрочного слоя;
- рабочий `deadline` и долговременный `profile.answer_language` присутствуют в
  разных блоках контекста и поэтому влияют на следующий ответ;
- одинаковый ключ можно хранить независимо в working и long-term;
- `startNewTask` очищает short-term и working, но сохраняет long-term;
- после создания нового экземпляра агента долговременная память и имя новой задачи
  восстанавливаются;
- JSON действительно содержит отдельные секции каждого слоя и остаётся совместим
  со старыми версиями сохранений.

Запуск тестов:

```shell
./gradlew :core:jvmTest
```

Для живого прогона с моделью:

```shell
./gradlew :cli:day11 -q --console=plain
```

Сценарий сначала сохраняет срок и состав релиза в working, а язык, технологию и
политику аналитики — в long-term. Первый ответ должен учитывать оба слоя. После
старта новой задачи срок и состав исчезают из контекста, а язык, технология и
политика остаются и продолжают влиять на ответ.
