# День 18 — планировщик и фоновые задачи

## Что работает в фоне

Планировщик находится в MCP-сервере, а не в мобильном приложении. Поэтому сбор
продолжается при закрытии приложения, пока работает команда `./gradlew :server:run`.
Push-уведомлений нет. Пока приложение открыто, агент сам добавляет сводку в диалог
с заданной частотой. При закрытом приложении данные продолжают копиться, а получить
их можно после открытия через `/weather-summary`. После перезапуска приложение само
находит активный сбор на MCP-сервере и возобновляет автоматический вывод.

Данные сохраняются в `server/server-data/weather-scheduler.json`. Каталог исключён из Git,
но не удаляется при перезапуске сервера. В JSON находятся настройки расписания и до
1000 последних замеров на каждый город.

## MCP-инструменты

- `schedule_weather_collection(city, interval_minutes)` создаёт или обновляет задачу.
  Первый замер выполняется сразу и возвращается агенту вместе с температурой,
  ощущаемой температурой, влажностью, ветром и состоянием погоды. Допустимый
  интервал — от 1 до 1440 минут.
- `get_weather_summary(city?)` агрегирует сохранённые замеры. Если задание одно,
  город можно не указывать.
- `get_active_weather_collection()` возвращает активный сбор, чтобы приложение
  восстановило автоматические сводки после перезапуска.
- `cancel_weather_collection(city?)` останавливает новые замеры, не удаляя старую историю.
  Следующий запуск для этого города создаёт новый период, новый ID и счётчик с одного.
- Инструмент Дня 17 `get_current_weather(city)` продолжает работать без расписания.

Сводка содержит количество замеров, начало и конец периода, минимальную, среднюю и
максимальную температуру, среднюю влажность, средний ветер и последний снимок погоды.

## Проверка в приложении

1. В корне проекта запустить сервер и оставить терминал открытым:

   ```shell
   ./gradlew :server:run
   ```

2. Запустить Android-приложение, открыть вкладку «Агент» и убедиться, что MCP включён.
3. Создать расписание одной из фраз:

   ```text
   /weather-watch Тюмень 1
   Собирай погоду в Тюмени каждую минуту
   ```

   Агент вызовет `schedule_weather_collection`. Первый замер уже будет в JSON.
4. Сразу запросить сводку:

   ```text
   /weather-summary Тюмень
   Покажи сводку погоды по Тюмени
   ```

   Карточка под ответом покажет вызов `get_weather_summary` и агрегированный JSON.
5. Не отправляя новых команд, оставить приложение открытым. Через минуту агент сам
   добавит автоматическую сводку в диалог; число `samples` должно увеличиться.
6. Остановить задачу:

   ```text
   /weather-stop Тюмень
   Останови сбор погоды в Тюмени
   ```

   После нового `/weather-watch Тюмень 1` счётчик нового периода снова будет равен 1.

## Как остановить и снова запустить сервер

В том же терминале, где работает `./gradlew :server:run`, нажать `Ctrl+C`. Код
завершения 143 после ручной остановки допустим. После этого порт 8080 освобождается,
и сервер снова запускается той же командой.

Если терминал был закрыт, а сервер остался работать, найти процесс можно командой
`lsof -nP -iTCP:8080 -sTCP:LISTEN`, затем остановить указанный PID. Не следует
запускать второй сервер, пока порт занят.

## Автоматическая проверка

```shell
./gradlew :server:test :app:shared:testAndroidHostTest
```

Тесты используют память вместо рабочего JSON и управляемые часы: создают расписание,
имитируют наступление следующей минуты, проверяют второй замер, агрегацию и остановку.
Также настоящий MCP-клиент вызывает все три инструмента через тестовый HTTP-сервер.
