# День 34 — ассистент для работы с файлами проекта

## Проверка из приложения

Запустите Ollama с `qwen3.5:9b-q8_0` и обновлённый сервер `./gradlew :server:run`.
В приложении откройте вторую вкладку **«Файлы»**. Android Emulator использует
`http://10.0.2.2:8080`, iOS Simulator — `http://127.0.0.1:8080`, телефон — IP Mac в той же сети.
Отдельный RAG-индекс не требуется: ассистент работает с настоящими файлами через tooling.

Первый сценарий: нажмите **«Пример: найти использования компонента»**, затем
**«Выполнить задачу»**. Цель — найти использования `SupportAssistant`, прочитать
реализацию, вызовы и тесты, подготовить отчёт с путями и строками. Пользователь
не выбирает файлы: модель сама вызывает поиск и чтение.

Второй сценарий: **«Пример: обновить справку API по коду»** → **«Выполнить задачу»**.
Ассистент находит HTTP API поддержки, читает реализацию, контракты и тесты,
подготавливает отдельный Markdown-документ. Если выбранный документ уже существует,
его нужно прочитать перед обновлением. Можно написать свою цель вместо примера.

Экран показывает ход работы, список прочитанных файлов, журнал инструментов,
итог и unified diff. Перед подготовкой документа нужны три разных непустых файла.
Кнопка **«Сохранить файлы»** применяет именно показанный план на Mac в рабочем
проекте, а не на телефоне. Результат находится в `docs/generated/day34/`.
Документ реально создаётся или изменяется; исходники приложения не перезаписываются.
Последняя задача и diff сохраняются на сервере и восстанавливаются при возвращении
на вкладку. Остановка сервера прерывает незавершённый запуск, но сохраняет готовые результаты.
Кнопка сохранения находится над результатом и журналом. Пока идёт работа, она
недоступна; после сохранения остаётся со статусом **«Файлы уже сохранены»**.
Для получения нового diff выберите цель и снова нажмите **«Выполнить задачу»**.

## Как ассистент выбирает операции

`tools/day34/file_agent.py` реализует цикл локальной Ollama: цель → JSON-действие
модели → реальный инструмент → его результат модели → следующее действие.
Заранее заданных списков исходных файлов для двух сценариев нет.

Доступны `list_files`, `search`, `read_file`, `write_file`, `diff`, `finish`.
`search` — буквальный поиск по нескольким файлам с путями и номерами строк.
`read_file` возвращает строки, SHA-256 полного файла и признак усечения.
`write_file` подготавливает полную новую версию одного документа; запись в
рабочий проект выполняется отдельным шагом сохранения. Прочитанные файлы и их
хеши добавляются в документ программно. Обычный текстовый ответ без чтения трёх
файлов и подготовленного документа не считается выполненной задачей.

Читаются отслеживаемые Git текстовые файлы README, документации и исходников
в `core`, `app`, `server`, `cli`, `tools`, `gradle`, `docs`. Секреты, скрытые файлы,
каталоги сборки, бинарные файлы и символические ссылки исключены. Лимит файла —
80 КБ, одного чтения — 120 строк / 10000 символов; поисковая выдача — 60 совпадений.
Усечения и пропуски указаны в ответах инструментов. Это не проверка всего диска.
Автоматически созданные отчёты не добавляют новые использования в обычный поиск.

Запись ограничена `docs/generated/day34/<имя>.md`, один документ за запуск.
Ассистент не получает shell, произвольные URL, удаление файлов или изменение конфигурации.
Перед применением сверяются хеши прочитанных файлов, исходная версия документа
и наблюдения поиска. Изменившийся файл не перезаписывается — нужно подготовить новый diff.
Повторное применение того же плана не дублирует содержимое. Значения из файлов
считаются недоверенными данными, а не инструкциями для инструментов.

Лимиты — 18 действий, бюджет контекста и не более 10 минут на задачу. Ошибка,
превышение лимита или незавершённое действие модели не выдаются за готовый документ.
Вывод модели требует чтения человеком: наличие реальных источников не доказывает
смысловую корректность каждого предложения.

## CLI и воспроизведение

```sh
python3 tools/day34/file_agent.py --goal 'Найди использования SupportAssistant и подготовь отчёт с путями и строками' --output day34-data/usage
python3 tools/day34/file_agent.py --goal 'Подготовь справку HTTP API поддержки по реализации, типам данных и тестам' --output day34-data/api
```

В папке результата: `job.json`, `trace.json`, `plan.json`, `changes.diff`.
Для применения: `python3 tools/day34/file_agent.py --apply-plan day34-data/usage/plan.json`.
Флаг `--apply` у запуска по цели позволяет сразу применить готовый план из CLI.

Повтор без модели: `python3 tools/day34/file_agent.py --replay day34-data/usage/trace.json --output day34-data/repeated`.
Исполняются те же файловые действия, проверяются хеши прочитанных файлов и результаты
поиска. На прежнем входном состоянии diff совпадает. Если после сохранения документ
уже содержит тот же результат, новая запись не требуется. Если изменились прочитанные
исходники, документ, список/результат поиска, повтор отклоняется: выполните цель заново.
Генерация нового ответа LLM может отличаться; точное воспроизведение относится к журналу.

В репозитории есть небольшой журнал проверенного примера, который не требует Ollama:

```sh
python3 tools/day34/file_agent.py --replay tools/day34/examples/api-reviewed-trace.json --output day34-data/example-repeat
```

На сохранённой версии проекта он возвращает `no_changes`: справка уже соответствует
результату. Это реальные действия локальной модели; формулировки документа уточнены
Codex при проверке исходников. Происхождение записано в поле `origin` журнала.
Исходные ответы модели и diff сохранены локально в `day34-data/app/<ID>/*-model.*`.
Образцы результата: `docs/generated/day34/support-assistant-usage.md` и `support-api.md`.
Итоги проверки — `docs/day34-validation.json`. После изменений исходников пример может
ожидаемо отклониться из-за несовпадения хешей: тогда нужно запустить новую цель с Ollama.

HTTP API: `POST /api/file-tasks` с `{"goal":"..."}` возвращает `202` и ID;
`GET /api/file-tasks/latest`, `GET /api/file-tasks/<ID>` — состояние и diff;
`POST /api/file-tasks/<ID>/apply` с `{}` — сохранение проверенного плана.
API предназначен для доверенной локальной сети, не для публикации в интернете.

Проверки: `python3 -m unittest discover -s tools/day34 -v` и
`./gradlew :server:test :core:jvmTest :app:androidApp:assembleDebug :app:shared:compileKotlinIosSimulatorArm64`.
