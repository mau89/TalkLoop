# День 19 — композиция MCP-инструментов

## Чем это отличается от Дня 18

В Дне 18 планировщик и сводка вызывались независимо и были связаны сохранёнными
данными. В Дне 19 агент вызывает один инструмент-оркестратор, а тот завершает три
этапа подряд в рамках одного запроса.

## Инструменты

- `search_weather_data(city)` получает структурированный снимок погоды из wttr.in.
- `summarize_weather_data(weather_data)` принимает именно этот снимок и формирует
  Markdown.
- `save_weather_report(city, report_markdown)` сохраняет полученный Markdown.
- `run_weather_report_pipeline(city)` автоматически выполняет все три операции.

Файлы сохраняются в `server/server-data/reports`. Каталог уже исключён из Git.
Имя файла создаёт сервер, поэтому клиент не может передать произвольный путь.

## Проверка в приложении

1. В корне проекта запустить MCP-сервер и оставить терминал открытым:

   ```shell
   ./gradlew :server:run
   ```

2. Открыть вкладку «Агент» и отправить:

   ```text
   /weather-report Тюмень
   ```

3. Агент должен показать один вызов `run_weather_report_pipeline` и результат:

   ```text
   1. search_weather_data — данные получены
   2. summarize_weather_data — Markdown сформирован
   3. save_weather_report — файл сохранён
   ```

4. В карточке MCP структурированное поле `steps` содержит три элемента. `output`
   первого совпадает с `input` второго, а `report_markdown` второго передан в
   `input` третьего.
5. Путь из `file_path` указывает на созданный Markdown-файл с актуальной погодой.

## Автоматическая проверка

```shell
./gradlew :server:test :app:shared:testAndroidHostTest
```

Тест запускает оркестратор настоящим MCP-клиентом, проверяет порядок этапов,
равенство переданных JSON-данных и содержимое, которое получил файловый этап.
