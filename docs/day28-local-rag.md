# День 28. Локальная LLM + RAG

Цель — проверить существующий RAG TalkLoop с локальной генерацией и сравнить
результаты с облачной моделью. Модель работает на Mac, Android-эмулятор обращается
к нему по локальной сети; веса модели не запускаются внутри телефона.

## Шаг 1. Использовать готовый индекс

Используется индекс Дня 21: 53 русских рецепта Викиучебника, 32 122 слова,
273 фиксированных фрагмента. Модель эмбеддингов — локальная ONNX
`intfloat/multilingual-e5-small`, вектор размерности 384.
Корпус, токенизатор, ONNX-модель и индексы уже находятся в `day21-data`.

**Для чего:** искать по той же книге из Недели 6, без повторного скачивания
источников и без внешнего сервиса эмбеддингов. URL в ответах — метаданные
сохранённых источников; генерация не открывает эти страницы в интернете.

## Шаг 2. Запустить локальные сервисы

Оставить Ollama запущенной с уже скачанной `qwen3.5:9b`. Запустить поиск:

```sh
./gradlew :server:run --console=plain
```

**Для чего:** Ollama предоставляет генерацию на порту 11434, сервер индекса —
поиск на порту 8080. Поиск загружает модель ONNX и токенизатор с диска.
Первоначальная подготовка и загрузка весов требуют интернета; повторный поиск
и генерация используют локальные файлы.

## Шаг 3. Включить RAG в приложении

1. В «Агент → Настройки» выбрать «Ollama · локально» и применить модель.
2. Для Android Emulator использовать Ollama `http://10.0.2.2:11434`,
   сервер книги `http://10.0.2.2:8080`.
3. Отключить MCP погоды и внешних книг.
4. Включить «Использовать кулинарную книгу (RAG)» и проверку цитат.
5. Задать вопрос о конкретном рецепте.

**Для чего:** генерация, память задачи и проверка смысла цитат используют один
локальный `OllamaLlmClient`; облачный клиент в этот путь не подставляется.
Поиск выполняется локально. Другие учебные вкладки приложения по-прежнему могут
использовать Claude, поэтому проверяем именно вкладку «Агент».

## Шаг 4. Исправить совместимость полного пайплайна

При проверке кода обнаружено, что память RAG и проверка цитат принимали
только статусы завершения Anthropic. Нормальное завершение Ollama `stop`
ошибочно считалось оборванным. Теперь `LlmAnswer.complete` принимает
`end_turn`, `stop_sequence` и `stop`; обрыв `max_tokens` остаётся неполным.
Исправление покрыто тестами памяти, черновика, проверки смысла и оценки ответа.

Следующий реальный запрос остановился до генерации: консервативная оценка входа
18 551 превышала рабочее окно 16 384. Рабочее окно Ollama увеличено до 32 768,
с сохранением проверки размера и резерва под ответ. Это оценка по UTF-8 байтам,
а не фактическое число токенов. Ошибка исходной попытки сохранена отдельно.

**Для чего:** локальная модель должна проходить весь пайплайн, включая память
и проверку, а не только отвечать на простой запрос без RAG.

## Шаг 5. Повторить сравнение

```sh
# Локальная генерация, ключ Claude не нужен:
./gradlew :cli:day28 -q --console=plain --args='--provider local --repeats 3'

# Отдельный облачный прогон, использует существующий ключ Claude:
./gradlew :cli:day28 -q --console=plain --args='--provider cloud --repeats 3'
```

Результаты атомарно сохраняются после каждой попытки в `day28-data/local.json`
и `day28-data/cloud.json`. `--questions q04,q07,q10` выбирает контрольные вопросы;
`--output` задаёт другой файл. Ошибки сохраняются, а не маскируются успешным ответом.
По умолчанию используется только локальный провайдер; ключ облака даже не читается.

**Для чего:** сравнить простую пару чисел (булочка), несколько норм ингредиентов
(оливье) и корректный отказ при недостатке материалов (борщ). Каждый вопрос
повторяется трижды, каждый раз с новой историей и той же памятью RAG, инвариантами
и проверкой цитат, что в приложении. Эталонные ответы не передаются модели.

Настройки поиска одинаковые: фиксированный индекс, top-K 10 → максимум 5,
порог сходства 0,86, уточнение запроса и цитаты включены. Модели могут по-разному
восстановить поисковый запрос; все поисковые трассы сохраняются. Это сравнение
полных пайплайнов, а не генерации из искусственно одинакового контекста.
Локальный генератор и проверяющий — Qwen3.5 9B; в облаке генератор — Haiku,
проверяющий — Sonnet. Результат отражает также различие проверяющих моделей.

## Шаг 6. Оценить результат

- Качество: числа и варианты рецепта, наличие настоящих цитат, корректный отказ.
  Автоматические признаки дополняются ручным чтением ответов и исходных фрагментов.
- Скорость: полное время обработки, включая память, поиск, генерацию, проверку
  и возможное исправление. Первый замер не исключён и может включать загрузку модели.
- Стабильность: доля технически завершённых запросов и повторяемость успешных
  ответов по каждому вопросу. Три повтора дают небольшую проверку, а не гарантию.

При локальном контрольном прогоне тестовый процесс запускается с macOS sandbox:
исходящие соединения разрешены только к localhost. Внешний запрос из такого
процесса блокируется, запрос к Ollama разрешён. Это ограничение тестового
процесса и его потомков, а не отключение интернета на всём Mac.

Повторить такой прогон на macOS после подготовки зависимостей:

```sh
/usr/bin/sandbox-exec -p '(version 1)(allow default)(deny network-outbound)(allow network-outbound (remote ip "localhost:*"))' \
  ./gradlew --offline --no-daemon :cli:day28 -q --console=plain \
  --args='--provider local --repeats 3'
```

`--no-daemon` нужен, чтобы дочерний процесс генерации не был запущен ранее
созданным Gradle-демоном вне ограничения. Ollama и сервер индекса запускаются
отдельно; офлайн-режим их вычислений проверяется через локальные файлы модели
и отдельный запуск ONNX-worker под тем же ограничением сети.

## Фактический результат 9 октября 2026

Выполнено 18 независимых попыток: по три вопроса, каждый по три раза,
отдельно для Qwen3.5 9B и облачного пайплайна Haiku/Sonnet.

**Локальный пайплайн:** семь из девяти запросов технически завершились.
Все три ответа про булочку верно указали 170–180 °C и 12–15 минут, с настоящими
цитатами. На оливье один из трёх запросов дал правильные 200 г мяса,
200 г картофеля и 150 г майонеза; два остановились на проверке неподтверждённого
уточнения памяти, даже после предусмотренной попытки исправления.
На борщ получены три корректных отказа без выдуманных количеств.

**Облачный пайплайн:** все девять запросов технически завершились.
Три правильных ответа про булочку и три корректных отказа на борщ.
Ни один из трёх вопросов про оливье не получил полного ответа: в двух случаях
не подтверждены точные цитаты, в одном модель вернула отказ при найденном источнике.
Это защищает от публикации выдумок, но не решает вопрос пользователя.

**Скорость:** медиана полного времени технически завершённых запросов —
34,651 с локально и 16,651 с в облаке. Для булочки: 34,651–47,698 с локально,
9,208–20,551 с в облаке. Для борща: 4,909–8,711 с локально, 3,366–9,758 с в облаке.
Единственный успешный локальный ответ об оливье занял 49,923 с.
Быстрые локальные ошибки памяти (13,903 и 18,627 с) в медиану завершённых
запросов не включены. Медиана всех девяти попыток также сохранена в отчёте.

**Качество и стабильность:** ручная оценка приняла семь из девяти локальных
результатов и шесть из девяти облачных. Булочка и отказ на борщ устойчивы в этой
малой выборке; локальная память на оливье нестабильна. Облако технически стабильнее,
но его проверка цитат на оливье не дала полного ответа ни разу. Данных недостаточно
для общего вывода о превосходстве какой-либо модели.

Автоматические шаблоны дали ложные пропуски для локальных ответов: они ожидали
диапазон через тире, а Qwen написала «от 170 до 180», «от 12 до 15»; шаблон про
мясо не учитывал длинную корректную формулировку. Исходные автоматические оценки
сохранены без исправления; ручная оценка вынесена отдельно. У Qwen встречаются
неудачные падежи в названии булочки, хотя численные факты верны.
Все десять опубликованных цитат повторно сопоставлены с текстом фрагментов.

Полный локальный прогон намеренно закончен ненулевым кодом: два сбоя памяти
не объявлены успешными. При этом сохранены результаты всех девяти попыток,
включая семь завершённых локальных запросов при блокировке внешней сети
тестового процесса. Отдельный ONNX-worker также успешно выполнил поиск
под тем же сетевым ограничением. Ollama подтвердила загруженную `qwen3.5:9b`
с окном 32 768; все генерации, память и проверки шли к этому локальному API.
Интернет на всём Mac и в отдельном процессе сервера Ollama не отключался.
