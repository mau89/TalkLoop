# День 23 — фильтрация и уточнение запроса

В существующем агенте первой вкладки добавлен второй этап RAG: локальное упрощение
запроса → поиск кандидатов → порог сходства → удаление повторных chunk_id →
ограничение числа источников → вопрос с отобранными фрагментами → LLM.
Используется фильтр, отдельная модель реранкинга не нужна.

## Как проверить в приложении

1. Запустите локальный сервер: `./gradlew :server:run`. Индекс Дня 21 должен быть подготовлен.
2. В первой вкладке «Агент» включите «Использовать кулинарную книгу (RAG)».
3. Без «Улучшенного поиска» работает обычный RAG: исходный запрос, пять фрагментов, без порога.
4. Включите «Улучшенный поиск»: это включает уточнение запроса и фильтрацию.
5. В «Настройки» → «Кулинарная книга» можно независимо переключить оба этапа,
   изменить порог и top-K до/после фильтра. Исходные настройки: 10 кандидатов,
   порог **0,86**, максимум **5** источников после фильтра; индекс «Фиксированный».
6. «Подробнее» у ответа показывает исходный и поисковый запросы, число кандидатов,
   источники, переданные модели, и причины отсечения. Номера [1], [2] относятся
   только к оставшимся фрагментам, порядок соответствует карточкам источников.

Переключатели действуют на следующий запрос, сохраняя текущую переписку и память.
Для независимого сравнения начните новый диалог перед каждым режимом: иначе прошлый
ответ будет частью истории. Отключение RAG даёт третий, прежний режим без поиска;
в сравнении Дня 23 **оба режима используют RAG**.

Три вопроса для видео:

- По кулинарной книге: когда добавляют плавленый сыр в «Луковый суп 1» и сколько после этого варят?
- При какой температуре и сколько минут по книге выпекают «Булочку с корицей 1»?
- Приведи точные количества свёклы, капусты и мяса для борща из этой кулинарной базы. Если такого рецепта нет в доступных материалах, сообщи об этом.

Для первых двух видно сокращение контекста 5 → 1. Для борща: обычный RAG
получает пять похожих, но посторонних фрагментов; улучшенный отсеивает все десять
кандидатов. Это демонстрация фильтрации, не обещание, что каждый ответ станет точнее.

## Что делает query rewrite

`rewriteRagQuery` выполняется локально, без дополнительного вызова LLM:
убирает начальные «Пожалуйста, подскажи», «По кулинарной книге:», некоторые
концевые «по книге / в книге / из книги», нормализует пробелы. Названия,
варианты рецепта, числа, единицы и отрицания сохраняются. Формулировки
«не по книге» не переписываются. Если упрощение даёт пустую строку, используется
исходный запрос. Это консервативное упрощение; оно не исправляет опечатки,
не раскрывает местоимения и не добавляет информацию из истории.

Переписанная строка используется только для эмбеддинга и поиска. Исходный вопрос
остаётся в истории и в контексте LLM. Ожидания контрольных вопросов модели не передаются.
Кандидаты ниже порога и сверх итогового лимита в промпт не попадают. Порог включительный:
сходство 0,86 проходит при пороге 0,86. Итоговые источники сортируются по сходству,
повторные chunk_id удаляются; это не удаление смысловых повторов разных чанков.

Если ничего не осталось, LLM получает исходный вопрос и пустой контекст, с инструкцией
сообщить о недостатке сведений. Поиск и rewrite локальные; генерация ответа по-прежнему
обращается к Anthropic API. Автоматического веб-поиска или ответа из общих знаний нет.
Ошибка индекса останавливает запрос до вызова LLM; пустая выборка не является ошибкой.

## Настройка порога

Порог 0,86 проверен до итогового прогона ответов на восьми отдельных запросах:
пять рецептов вне набора Дня 22 (аджика, вальдорфский салат, ткемали, шведские
фрикадельки, эчпочмак), два отсутствующих рецепта (тирамису, пицца маргарита) и
один вопрос про замену сопла Bambu Lab A1. Исходные результаты:
[калибровка](day23-calibration.json).

На этих примерах после rewrite:

- Порог 0,84: нужные рецепты найдены в 5/5, один из трёх запросов вне базы проходит ошибочно.
- Пороги 0,85 / 0,86 / 0,87: нужные рецепты 5/5, ошибочные совпадения 0/3.
- Порог 0,88: нужные рецепты уже 4/5, ошибочные совпадения 0/3.
- Порог 0,90: нужные рецепты 2/5, ошибочные совпадения 0/3.

Выбрано 0,86, top-K 10 → 5. Настройки зафиксированы для итогового сравнения.
У эчпочмака максимальное сходство выросло с 0,858090 до 0,874441: без rewrite
фильтр отбрасывает нужный рецепт, с rewrite он проходит.
Это небольшая проверка на данном фиксированном индексе и `multilingual-e5-small`.
Оценка сходства не является вероятностью. Контрольные вопросы известны с Дня 22,
это повторный регрессионный прогон, а не слепая оценка на новой выборке.
Для индекса «По разделам», другой модели, корпуса или формулировок порог нужно проверять заново.

на большинстве уже ясных вопросов ничего не меняет; его отдельный эффект заметнее
на калибровочном вопросе об эчпочмаке. Токены E5 не равны платным токенам Claude.

- Автоматические признаки: 10/10 в обоих режимах. Проверка по шаблонам пропускает
  ошибку q01 со словом «почти»; ручная оценка записана отдельно.
- Нужные рецепты найдены и процитированы в 9/9; отсутствующие номера цитат — 0.
- Все 20 ответов завершены, ошибок поиска/API нет.
- Входные токены Claude: **39 963 → 29 302**, снижение **26,7%**.
- Выходные токены: 1 245 → 1 216; суммарные: 41 208 → 30 518, снижение 25,9%.
- Суммарное время десяти ответов: 36,817 → 34,291 секунды. Один прогон,
  последовательный порядок обычный/улучшенный; это не устойчивый тест скорости.

На этой выборке улучшился состав контекста и снизился расход, а точность ответов
осталась той же. Модель всё ещё может ошибиться при пересказе верного источника.
Отсутствие фрагментов после порога не доказывает отсутствия рецепта во всей базе.

## Воспроизведение и проверки

```shell
./gradlew :server:run
# В другом терминале — только локальный поиск, ключ API не нужен:
./gradlew :cli:day23 --args='--calibrate --output day23-data/calibration.json'
./gradlew :cli:day23 --args='--retrieval-only --output day23-data/retrieval-ablation.json'
# 20 ответов через API, ключ как в приложении:
./gradlew :cli:day23 --args='--output day23-data/comparison.json'
# Изменить параметры:
./gradlew :cli:day23 --args='--before 10 --after 3 --threshold 0.86 --output day23-data/comparison-k3.json'
```

На этом компьютере использован `--direct`, чтобы обходить неработающий системный
Java-прокси только в процессе CLI. В приложении основной агент использует прямой
транспорт из Дня 22. Повторный прогон модели может дать другие формулировки.

Проверки: 133 теста core на JVM и iOS Simulator, 19 Android host-тестов,
Android debug-сборка, компиляция общего UI для iOS и CLI. Восемь новых тестов
проверяют сохранение чисел/отрицаний, границу порога, лимиты, повторы и порядок,
независимое включение этапов, исходный вопрос для LLM, отсечение всего контекста,
смену настроек во время запроса, некорректные ответы поиска и отмену.

В Android-эмуляторе проверены русские вопросы про луковый суп и борщ,
чекбокс улучшенного поиска, результаты 10 → 1 и 10 → 0 и раскрытие трассы поиска.
Изменения находятся в ветке `🔥-День-23.-Реранкинг-и-фильтрация`.
Доставка Дня 23: один итоговый коммит и push по явному разрешению пользователя.
