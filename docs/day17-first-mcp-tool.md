# День 17 — погода через MCP

## Что здесь делает MCP

MCP можно представить как понятный переходник между агентом и внешним сервисом.
Агент знает, что ему нужен инструмент погоды, но ему не нужно знать URL и формат
wttr.in. Эти детали скрывает MCP-сервер.

Полный путь одного запроса:

```text
Пользователь пишет агенту «Какая погода в городе Екатеринбург?»
        ↓
Обычный TalkLoopAgent передаёт погодный запрос McpWeatherToolProvider
        ↓
Провайдер спрашивает у MCP-сервера список инструментов
        ↓
Сервер сообщает: есть get_current_weather, ему нужен параметр city
        ↓
Агент вызывает get_current_weather({"city":"Екатеринбург"})
        ↓
MCP-сервер получает текущую погоду по названию города через wttr.in
        ↓
Агент получает JSON с температурой, осадками и ветром
        ↓
TalkLoopAgent использует результат в обычном ответе
```

## Зарегистрированный инструмент

Имя инструмента: `get_current_weather`.

Его вход описан JSON Schema:

```json
{
  "type": "object",
  "properties": {
    "city": {
      "type": "string",
      "description": "Название города, например Екатеринбург",
      "minLength": 2
    }
  },
  "required": ["city"]
}
```

Пример результата:

```json
{
  "city": "Екатеринбург",
  "country": "Россия",
  "observed_at": "2026-09-24T12:00",
  "temperature_c": 8.5,
  "feels_like_c": 5.2,
  "humidity_percent": 74,
  "precipitation_mm": 0.0,
  "wind_speed_kmh": 14.0,
  "condition": "переменная облачность"
}
```

Данные в приложении будут отличаться, потому что wttr.in возвращает настоящую
погоду на момент вызова.

## Проверка по шагам

### Шаг 1. Запустить MCP-сервер

Из корня проекта выполнить:

```shell
./gradlew :server:run
```

Терминал должен остаться открытым. Сервер слушает `http://localhost:8080/mcp`.

### Шаг 2. Запустить приложение

Открыть Android-приложение и перейти на обычную вкладку «Агент».

В настройках агента убедиться, что переключатель «MCP-погода» включён. Затем написать:

```text
/weather Екатеринбург
```

Можно проверить и обычной фразой: `Какая погода в городе Екатеринбург?`.

### Шаг 3. Проверить три результата

Под ответом появится карточка `MCP вызван: get_current_weather`. Она должна показать
отправленный аргумент:

```json
{"city":"Екатеринбург"}
```

Там же должен появиться результат с реальной температурой, ощущаемой температурой,
влажностью, осадками, ветром и состоянием погоды. Это доказывает `tools/call` и
возврат результата.

Сам диалог должен содержать обычный человеческий ответ, например: «Сейчас
около 8 °C, ощущается как 5 °C; лучше надеть куртку». Это доказывает, что агент не
просто получил JSON, а использовал его.

Для ответа агента нужен Anthropic API key.

### Шаг 4. Проверить отключение

Открыть настройки вкладки «Агент» и выключить «MCP-погода». После этого агент не
создаёт MCP-клиент и не подключается к серверу. Повторное включение возвращает инструмент.

## Подключение к Codex

В проект добавлен `.codex/config.toml` с сервером `talkloop_weather`. После запуска
сервера и повторного открытия проекта команда `/mcp` показывает сервер и его инструмент.
`/mcp` только открывает список и статус; сам вызов Codex выбирает по обычному запросу.

Чтобы временно отключить сервер, не удаляя настройку, изменить в файле:

```toml
enabled = false
```

## Автоматическая проверка

```shell
./gradlew :server:test
```

Ожидаемый итог — `BUILD SUCCESSFUL`. Тесты используют предсказуемый фейковый ответ
погоды, но подключают настоящий MCP-клиент: проверяют регистрацию инструмента,
обязательный параметр `city`, успешный вызов и понятную ошибку для неизвестного города.
