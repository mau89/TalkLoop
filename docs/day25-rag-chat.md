# День 25. RAG-чат с памятью задачи

В существующей первой вкладке «Агент» работает чат с локальной кулинарной книгой,
полной сохраняемой перепиской, памятью задачи, источниками и точными цитатами.
Добавлен также CLI, который продолжает тот же сохранённый диалог между запусками.

## Проверить в приложении

1. Открыть первую вкладку «Агент». Включить «Использовать кулинарную книгу (RAG)»
   и оставить включённым «Подтверждать ответ цитатами». Локальный сервер книги должен
   работать; адрес для Android-эмулятора — `http://10.0.2.2:8080`.
   Кнопка «Новая задача» находится прямо в карточке «Память задачи», рядом с
   «Открыть». Она показывает подтверждение; «Начать заново» очищает текущий диалог,
   «Отмена» оставляет его. В настройках также доступен прежний сброс диалога.
2. Отправить: «Цель — подготовить список продуктов для оливье примерно на четыре
   порции. Не предлагай свои замены. Работаем с рецептом из книги 1959 года.
   Сколько мяса, картофеля и майонеза нужно?»
3. Спросить: «А сколько майонеза для него?» Ожидается 150 г, а не общий рецепт.
4. Спросить: «Теперь отвечай одним предложением. Мясо в нём только отварное или
   допустимо жареное?» Ожидаются оба варианта из книги, источник и цитата.
5. Открыть «Память задачи»: там видны цель, рецепт, уточнения, ограничения и термины.
   В «Подробнее» видны восстановленный вопрос, поиск и расход памяти.
   Перезапустить приложение, снова включить RAG и продолжить коротким уточнением.
   «Новая задача» очищает переписку и память текущей задачи.

Эти три вопроса подходят для видео. В названии варианта указан 1959 год:
раздел «Основной рецепт» статьи об оливье не совпадает с этим рецептом на четыре порции.
Термин, например «заправка = Майонез 1», может попасть в уточнения или термины;
обе группы передаются модели. Карточка показывает сохранённое состояние, а не
новый ответ модели на каждый клик.

## Как работает каждый ход

Вопрос и предыдущая память → обновление памяти и самостоятельный вопрос →
локальный поиск → чанки с метаданными + текущий вопрос + память → LLM →
проверка буквальности цитат → отдельная проверка смысла → ответ и сохранение.

Для памяти используется выбранная модель агента. Цель, текущий рецепт, уточнения,
ограничения и термины сохраняются как дословные отрывки пользовательских сообщений
с номером пользовательского хода. Приложение проверяет принадлежность каждого
отрывка; сведения из ответов и рецептов нельзя записывать как пользовательское
уточнение. Модель раскрывает «его», «этот вариант», «после добавления» перед поиском.
Цель остаётся действующей при смене блюда, а отменённое требование заменяется новым.

Полный архив сохраняется и показывается отдельно от ограниченного окна модели.
В проверочных сценариях окно составляет 10 сообщений; для обновления памяти
передаются четыре последних сообщения, текущая реплика и исходные пользовательские
реплики, на которые ссылаются сохранённые факты. Старую цель не приходится
повторять в каждом вопросе. Полный архив не отправляется целиком в LLM.
При миграции старого формата доступная ранее история становится началом архива;
ранее удалённые коротким окном реплики восстановить невозможно.

Факты книги берутся только из чанков текущего поиска. Память задаёт намерение
пользователя, а предыдущий ответ не считается источником рецепта.
По умолчанию: fixed, similarity ≥ 0,86, top-K 10 → 5, rewrite и фильтр включены.
Если короткий запрос не даёт ни одного фрагмента, выполняется ещё один локальный
поиск по полному восстановленному вопросу с теми же порогом и лимитами.
Два таких повторных поиска понадобились в итоговом прогоне; порог не снижался.

Каждый завершённый ответ этого чата имеет раздел «Источники». У подтверждённого
ответа он содержит использованные URL, разделы и chunk_id, далее идут цитаты.
При отказе явно указаны отсутствие релевантных источников либо найденные материалы,
которые не подтвердили ответ. Эти материалы не выдаются за доказательство; цитаты
для неподтверждённых утверждений не создаются.

Обычный подтверждённый ход — три API-вызова: память, ответ, проверка смысла.
Невалидная память допускает одну корректировку, неверный/неподтверждённый черновик
ответа — одну корректировку с повторной проверкой. В расход завершённых ходов
включены все эти этапы; поиск и эмбеддинги локальные. При пустом контексте после поиска нет генерации
ответа и смысловой проверки, но обновление памяти уже использовало модель.
Сбой обновления памяти или поиска не записывает новый ход; неподтверждённый ответ
заменяется отказом, и пользовательское уточнение сохраняется вместе с ним.

Формат истории обновлён до v9, версии v1–v8 читаются. CLI сохраняет JSON атомарно,
блокирует одновременную запись двух процессов в один сеанс и прекращает запуск при
повреждённом/неподдерживаемом файле, сохраняя исходный файл. В приложении используется
его прежнее платформенное хранилище. Переписка и сеансы CLI находятся в игнорируемом
`day25-data`, ключ API — в прежних локальных настройках проекта.

## CLI и повторение

При работающем локальном сервере и настроенном ключе:

```sh
./gradlew --console=plain :cli:day25 --args='--direct'
```

Команды: `/state` — память задачи; `/history` — весь диалог;
`/new` — начать новую задачу; `/exit` — выйти.
По умолчанию используется `day25-data/chat.json`; следующий запуск продолжает его.
Другой сеанс: `--session day25-data/demo.json`.
`--direct` отключает системный прокси для процесса CLI; его можно опустить.

Повторить два независимых длинных сценария с реальными запросами к LLM:

```sh
./gradlew :cli:day25 --args='--direct --evaluate --output day25-data/scenarios.json'
```

Параметры: `--scenario lunch` / `--scenario salads`, `--server`, `--model`,
`--verifier-model`, `--strategy`, `--before`, `--after`, `--threshold`.
Каждый прогон создаёт новые сеансы и сохраняет отчёт после каждого хода.
Ожидания контрольных вопросов модели не передаются.

Таким образом, требование длинного диалога проверено с запасом относительно 10–15 сообщений.
Модели: `claude-haiku-4-5` для памяти/ответа, `claude-sonnet-5` для проверки смысла.
Сценарии выполнены последовательными непрерывными диалогами, а не изолированными вопросами.
Перед седьмым запросом оба агента пересозданы из файлов; память и архив восстановлены
точно. В этот момент первая цель уже отсутствует в окне из десяти сообщений.

- Цель и действующие ограничения сохранены в 24/24 ходах; ошибки обработки — 0.
- Раздел «Источники» есть в 24/24; подтверждённые ответы с нужным источником и
  цитатами — 23/24. Все 29 ссылок цитирования (20 разных цитат) буквально совпадают
  с найденными чанками, метаданные и номера источников соответствуют текущему поиску.
- Ручная оценка: 21 полный ответ, два замечания к ясности порядка готовности картофеля
