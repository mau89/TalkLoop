# День 33 — ассистент поддержки пользователей

## Запуск в приложении

1. Запустите на Mac Ollama с установленной `qwen3.5:9b-q8_0`.
2. Подготовьте FAQ: `.day21-venv/bin/python tools/day33/index_support.py`.
   Используется существующая локальная E5 Дня 21, без новых скачиваний.
   Если окружения или E5 ещё нет, сначала выполните `tools/day21/run.sh prepare`.
3. Запустите или перезапустите `./gradlew :server:run`, откройте свежую сборку приложения.
4. Выберите вторую вкладку **«Поддержка»**. Android Emulator использует
   `http://10.0.2.2:8080`, iOS Simulator — `http://127.0.0.1:8080`, телефон — IP Mac в той же сети.
5. **Елена → T1001**, вопрос «Почему не работает авторизация?»:
   `EMAIL_NOT_VERIFIED`, `emailVerified=false` → подтверждение почты, папка «Спам», повторное письмо.
6. **Максим → T1002**, тот же вопрос:
   Google OAuth, Android 1.0.0, `OAUTH_CALLBACK_SCHEME` → обновление до 1.1.0 или новее.
   Повторное подтверждение уже подтверждённой почты эту проблему не решает.
7. **Елена → T1003**, вопрос о недоступном сервере:
   `serverRunning=false` → запуск локального сервера и проверка адреса.

Под ответом видны клиент, ID и статус тикета, инструмент MCP, код ошибки и источники.
Кнопка **«Контекст тикета и фрагменты FAQ»** открывает реально полученные данные и тексты.
Можно задать уточнение: «Папку Спам уже проверила. Что дальше?».
Передаются две последние пары реплик этого тикета. Смена клиента/тикета очищает
диалог; история хранится в памяти экрана и не сохраняется после его закрытия.

## HTTP-сервис и цепочка ответа

- `GET /api/support/catalog` — демо-клиенты и краткие сведения о тикетах.
- `POST /api/support/ask` — вопрос и выбранное обращение:

```json
{"userId":"U1001","ticketId":"T1001","question":"Почему не работает авторизация?"}
```

Необязательное поле `history` — до четырёх реплик `{fromUser,text}` по 1000 символов.
Ответ содержит `answer`, `disposition`, `context`, `sources`, `usedSources`, `mcpTool`.

Для каждого вопроса ассистент вызывает настоящий Streamable HTTP MCP на
`127.0.0.1:8083/mcp`. Read-only инструмент `support_ticket_context(userId,ticketId)`
читает фиксированный `tools/day33/support-demo.json` и проверяет принадлежность
тикета выбранному клиенту. Изменение JSON видно на следующем запросе.

Затем RAG ищет по текущему вопросу в отдельном E5-индексе `day33-data`.
Код ошибки передаётся в контексте MCP для выбора подходящей причины, но не
подменяет тему поиска: вопрос о продукте не превращается в вопрос об ошибке входа.
В него входят только `docs/support/**/*.md`: JSON клиентов в индекс не попадает,
кулинарный корпус и документация разработчика не используются. До трёх фрагментов,
текущий контекст MCP и ограниченная история передаются локальной Ollama.

Сервис проверяет завершённость ответа, схему JSON и существование номеров источников.
`answered` означает ответ по источникам, `needs_info` — нужно уточнение, `escalate` —
рекомендуется оператор. Пустая выдача RAG приводит к уточнению без вызова модели.
Ошибки MCP/индекса/модели и неверные ссылки не выдаются за готовое решение.
Лимит — три минуты; одновременно готовится один ответ, второй запрос получает `409`.

## Учебные данные и границы

Облачные аккаунты, вход и клиенты вымышлены: в локальном TalkLoop не появилась
настоящая авторизация. JSON не содержит паролей, токенов и настоящих персональных
данных. Выбор демо-клиента и проверка `userId` не заменяют аутентификацию.
Для настоящей CRM пользователя нужно связывать с серверной сессией.
Локальный HTTP API предназначен для доверенной сети, не для публикации в интернете.

MCP только читает данные. Ответ не меняет аккаунт, не отправляет письмо, не закрывает
и не передаёт тикет сам. История, заметки и FAQ считаются недоверенным контекстом.
Проверка ссылок не доказывает смысловую правильность рекомендации модели.

После изменения FAQ повторите индексацию и перезапустите сервер.
Тесты: `./gradlew :core:jvmTest :server:test :app:androidApp:assembleDebug :app:shared:compileKotlinIosSimulatorArm64`,
`.day21-venv/bin/python -m unittest discover -s tools/day33 -v`,
`.day21-venv/bin/python -m unittest discover -s tools/day31 -v`.
