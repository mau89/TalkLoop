# День 24 — цитаты, источники и «не знаю»

В первой вкладке «Агент» добавлено подтверждение ответа цитатами. Модель возвращает
утверждения с chunk_id и дословными фрагментами; приложение проверяет их по тексту
найденных чанков, затем отдельная модель проверяет соответствие смысла. Только после
проверок публикуются ответ, использованные источники и цитаты.

## Как проверить в приложении

1. Запустите локальный сервер: `./gradlew :server:run`. Нужен готовый индекс Дня 21.
2. В первой вкладке «Агент» включите «Использовать кулинарную книгу (RAG)».
3. Оставьте включённым «Подтверждать ответ цитатами» — это новый режим Дня 24.
4. Спросите о рецепте: ответ содержит блоки «Ответ», «Источники», «Цитаты».
   Каждый использованный источник содержит URL, раздел и chunk_id.
5. Раскройте «Подробнее»: здесь видны результат проверки, число вызовов модели,
   токены проверки, поиск и кандидаты. Обычно выполняются два вызова генерации:
   черновик и проверка смысла. При ошибке возможна одна попытка исправления и
   повторная проверка: всего до четырёх вызовов. Слабый контекст даёт ноль таких вызовов.
6. Для сравнения снимите «Подтверждать ответ цитатами», оставив «Улучшенный поиск»
   включённым. Получится RAG Дня 23 с тем же поиском, но без обязательных цитат.

Переключатели действуют на следующий запрос и сохраняют историю. Для независимого
сравнения начните новый диалог в каждом режиме. В «Настройки» → «Кулинарная книга»
можно изменить порог и лимиты. В режиме подтверждения порог применяется обязательно,
даже если старый флаг фильтра был выключен. Исходно: фиксированный индекс,
переписывание запроса включено, сходство ≥ **0,86**, top-K **10 → максимум 5**.

Три русских вопроса для видео:

- При какой температуре и сколько минут по книге выпекают «Булочку с корицей 1»?
- Какие количества риса, мяса, моркови и растительного масла указаны для классического ферганского плова?
- Приведи точные количества свёклы, капусты и мяса для борща из этой кулинарной базы. Если такого рецепта нет в доступных материалах, сообщи об этом.

Первый показывает компактную проверяемую цитату, второй — числа и источник [2],
третий — локальный отказ с просьбой уточнить. Вопрос о температуре выпечки теперь
попадает в книгу при включённом MCP: раньше слово «температура» перехватывал инструмент погоды.

## Что проверяется

Пайплайн: вопрос → локальный rewrite → эмбеддинг/поиск → порог и top-K → вопрос с
чанками → структурированный ответ LLM → буквальная проверка цитат → проверка смысла
отдельной LLM → локальное оформление ответа.

- Каждый из 1–8 пунктов ответа обязан иметь 1–4 цитаты из текущих чанков.
- chunk_id должен принадлежать текущей выборке. Цитата должна быть одним фрагментом
  длиной 6–1200 символов; допускаются только различия пробелов/переносов. Регистр,
  числа и пунктуация сохраняются. Короткая строка ингредиента допустима.
- Публикуется совпавший фрагмент исходного текста, а не переписанная цитата модели.
  URL, раздел, название и номер берутся из метаданных индекса.
- Перечисляются только использованные источники; номера сохраняют позицию в выборке.
  Поэтому ответ может содержать [2] без [1], совпадая с карточками в «Подробнее».
- Проверяющая модель видит вопрос, утверждения, цитаты, названия и разделы.
  Ожидания контрольных вопросов и история ей не передаются. Проверяются числа,
  единицы, исходное сырьё/готовый продукт, вариант, порции, порядок и оговорки.
- При выдуманной цитате, неполном JSON, неподтверждённом утверждении или недоступной
  проверке черновик скрывается. Ошибку формата/цитаты/смысла модель может исправить
  один раз по тем же чанкам и замечаниям. Исправление снова проходит обе проверки;
  циклических повторов нет. В историю сохраняется только проверенный текст либо
  отказ. При техническом сбое предлагается повторить запрос; при недостатке
  сведений — уточнить рецепт. При отмене запроса результат не сохраняется.

Поиск и эмбеддинги локальные; генерация и проверка используют Anthropic API.
По умолчанию ответ пишет `claude-haiku-4-5`, смысл проверяет `claude-sonnet-5`.
Проверка добавляет время и расход токенов. В статистике учтены оба вызова и тариф
каждой модели; окно контекста основного запроса считается отдельно от проверки.

Если после порога ничего не осталось, ответ формируется локально:

> Не знаю по найденным материалам. Релевантных фрагментов недостаточно. Уточните название блюда, вариант рецепта или добавьте источник с нужными сведениями.

Для такого отказа источники и цитаты не создаются: подтверждать нечего. Ошибка
сервера/индекса остаётся ошибкой поиска. Пустая выборка не используется как
доказательство отсутствия рецепта во всей базе.

## Результаты десяти вопросов

Это исторический прогон до последующего исправления нестабильных отказов на оливье.
Исходные ответы и контрольные суммы кода в ручном отчёте сохранены на момент прогона.
Ниже отдельно приведены результаты исправления; прежние ответы ими не заменяются.

Прогон от 5 октября 2026 года использует тот же основной агент, стандартные кулинарные
инварианты, память 10 сообщений, сжатие выключено, MCP выключен. Для каждого ответа
создаётся новый агент. Обе стороны используют rewrite, порог 0,86 и top-K 10 → 5;
различается только подтверждение. Автоматического веб-поиска нет.

Исходные ответы и трассы: [day24-comparison.json](day24-comparison.json).
Ручная оценка и контрольные суммы: [day24-review.json](day24-review.json).

- Новый режим: **9 ответов с источниками и цитатами, 1 локальный отказ**.
- В каждом из 9 ответов есть URL, раздел, chunk_id и цитата. Вопрос о борще
  не имеет прошедших порог источников и корректно просит уточнить без LLM.
- Проверено 28 ссылок утверждений на цитаты: **27 разных опубликованных фрагментов**,
  все буквально входят в свои чанки. Повтор одной цитаты у двух утверждений
  отображается один раз.
- Модель одобрила смысл в 9/9 ответов. Ручная проверка полного покрытия цитатами:
  **8 полных, 1 частичный** (q05: «после вскипячения» отсутствует в цитате).
- Ручная оценка самих ответов: **9 полных и 1 частичный в обоих режимах**.
  q01 стал подробнее, но его формулировка готовности картофеля остаётся неоднозначной.
- Автоматические признаки прошли 10/10 в обоих режимах; в новом режиме они считаются
  по утверждениям, а не по блоку цитат. Поэтому числа в цитате не маскируют ошибку ответа.

Это улучшение проверяемости и обязательности отказа, а не доказательство идеальной
точности. Подлинная цитата не гарантирует правильного пересказа; модель проверки
может принять лишнюю оговорку. Все ограничения отражены рядом с соответствующими ответами.

Расход итогового прогона:

- Без подтверждения: 10 вызовов генерации, 29 302 входных / 1 232 выходных токена,
  суммарное время ответов 35,6 с.
- С подтверждением: 9 черновиков + 9 проверок, **48 038 входных / 4 936 выходных**,
  суммарное время ответов 83,4 с. Для борща — 0 вызовов и 0 токенов LLM.
- Из них черновики: 36 420 / 3 002; отдельная проверка: 11 618 / 1 934 токена.
  Эти числа включают только итоговый прогон; дополнительные проверки разработки
  в них не входят. Вызовы подсчёта токенов не являются вызовами генерации.

В раннем пробном прогоне проверка той же небольшой моделью пропустила ошибку
порядка добавления сыра и смешение 55 г вытопленного жира с 85–90 г исходного сала.
Проверку заменили отдельной моделью. Повторная проверка **тех же двух неверных
черновиков**, без новой генерации, отклонила оба:
[регрессионный отчёт](day24-verifier-regression.json). Это два дополнительных вызова
проверки вне итоговых 28 вызовов сравнения. Другой пробный ответ был отклонён за
подмену рекомендованной температуры масла обязательной. Короткие строки ингредиентов
перестали ошибочно отклоняться после изменения минимальной длины цитаты с 12 на 6 символов.

## Исправление нестабильных отказов на оливье

После сообщения пользователя с примером отказа вопрос воспроизведён дважды:
один ответ прошёл проверку, другой отклонён. Причина — не поиск: модель правильно
указывала количества, но склеивала заголовок «примерно на 4 порции» непосредственно
со строкой картофеля или майонеза, пропуская промежуточные строки списка.
Такого непрерывного фрагмента в чанке нет, поэтому буквальная проверка отклоняла ответ.

Уточнена инструкция о непрерывных цитатах. Для структурированного режима убрана
противоречащая инструкция старого RAG вставлять ссылки [1] в текст модели:
в этом режиме ссылки формирует приложение. Ошибочный черновик теперь получает
одну попытку исправления с конкретными замечаниями по тем же источникам. Исправленный
ответ обязан заново пройти буквальную и смысловую проверки. При повторной ошибке
ответ остаётся скрытым. Токены и стоимость исправления/повторной проверки учитываются
по фактическим вызовам и моделям, без увеличения окна исходного запроса.

В «Подробнее» видны понятная причина отказа и число попыток исправления. Техническая
недоступность проверки просит повторить запрос и не выдаётся за отсутствие рецепта.

Проверка после исправления:

- Тот же сохранённый неверный черновик успешно исправлен: одна непрерывная цитата
  списка, примерно четыре порции, мясо 200 г, картофель 200 г, майонез 150 г.
- Три новых независимых прогона вопроса в CLI вернули проверенные ответы с теми же
  нормами. Все опубликованные цитаты буквально входят в чанки.
- В приложении тот же русский вопрос вернул проверенный ответ, URL, раздел, chunk_id
  и цитату. Борщ по-прежнему даёт локальный отказ с нулём вызовов LLM.
- Пройдено 150 core-тестов на каждой из JVM/iOS Simulator и 20 Android host-тестов;
  Android-сборка и компиляция iOS UI прошли. Новые тесты проверяют исправление
  склеенной цитаты, повторную смысловую проверку, предел одной попытки,
  историю/отмену, технический сбой и учёт токенов/стоимости дополнительных вызовов.

Исходные данные до/после и исправленный черновик:
[day24-reliability.json](day24-reliability.json). Три удачных повтора не являются
гарантией успеха любого будущего запроса; проверки по-прежнему могут отклонить ответ.

## Повторение и проверки реализации

При готовом индексе и работающем локальном сервере:

```sh
./gradlew :cli:day24 --args='--output day24-data/comparison.json'
```

локальной настройке. API-ключ берётся из существующего `secrets.properties` или
переменной окружения, не записывается в отчёт. Отчёт атомарно сохраняется после
